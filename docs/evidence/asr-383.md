# Issue #383: two native Moonshine streaming recognizers

Implemented on 2026-11-17. The production inventory is exactly
`SpeechToTextMoonshineMediumEn` (English Medium Streaming, 245M) and
`SpeechToTextMoonshineSmallJa` (Japanese Small Streaming, 123M). Their labels,
model/language/runtime facts, palette, Models entries, graph dispatch, preparation
and independent standalone pages agree. New/reset default graphs explicitly use
Japanese Small; the English → Japanese example uses English Medium. There is
no language-selection port or language detection.

## Asset and runtime evidence

including cache ID/revision, file URLs, full hashes and chunk hashes: no forced
English weight download or checkpoint replacement. Total: **304,690,919 bytes**.

Japanese uses the official `small-streaming-ja/quantized_26_08_23` checkpoint,
confirmed against Moonshine's model catalog at
`d8d8fa29d05ca67441a7719e70099f9f48917a93`. The eight files total
**121,803,780 bytes**. `extension/moonshine-small-ja-assets.json` pins exact sizes,

`330a8fedc2c613a96902275ecf6f622bda1271d820221427c19ac2cea230ffee` is the
SHA-256 of the sorted-key JSON file inventory generated during review. Official
CDN responses expose `Access-Control-Allow-Origin: *`. Downloads were obtained
from the official URLs, then verified again by the normal ModelAssetCache in
real browser tests using a loopback mirror. Model weights are never packaged.

same older WASM** (`d0e783f6…`) which rejects `frontend.model.ort`. Real Japanese

needed by Transcriber. The WASM is unmodified. The two existing Emscripten JS

Both selected streaming models and the runtime are **MIT**, as confirmed in the

## Removal and compatibility audit

Deleted the four implementations: `SpeechToTextReazonSpeech`,
`SpeechToTextWhisper`, `SpeechToTextZipformerEn`, `SpeechToTextParakeetV3`.
Their workers/configuration/segmentation/simulation modules, model manifests,
Models cards, graph contracts/dispatch, dedicated Playground pages, fixtures,
tests, download/review/benchmark scripts and current guidance are gone.
The standalone Silero asset, Worker, cache/download path and sherpa runtime
archive/preparation are gone. Moonshine's own integrated endpointing is retained.
Kokoro's Japanese OpenJTalk frontend, voice asset and TTS dependencies remain.

Removed `parakeet.js` and its separate `onnxruntime-web` dependency. The npm
Moonshine dependency is unnecessary with the pinned release archive and was also
removed. Other translation/TTS ORT runtimes remain. Packaging/CI/Pages now stage
only the current speech inventory. Playground staging clears generated vendor
files before preparation so reused staging directories cannot publish old assets.

The old recognizer core was removed; its reusable typed event delivery and Worker
ownership live in `OptionalAsrNode`. Both thin concrete Nodes share the existing
incremental algorithm in `moonshine-stream.js`. Stop drains, Cancel terminates,
restarts own independent state, one PCM block is in flight and total queued PCM
is bounded at 480,000 samples (30 seconds). Native history is also bounded at
30 seconds, renewing after drain. Overflow fails visibly without dropping audio.

No removed-type aliases, loaders, imports, cache exports or graph conversions
were added. Unknown types fail ordinary validation with recreate/reset guidance.
Supported graphs still round-trip and Auto Save; unrelated Display/Speaker and
Graph Library version handling remains intact. Historical evidence under
`docs/evidence/` describes its original commit and is not active model guidance.

Audits:

- Targeted removed-name search across extension, web, scripts, tests, docs,
  workflows and package.json: **zero active references**, excluding historical
  evidence and ignored generated vendor bundles.
- Static relative imports across production `extension/` and `web/`: **zero
  missing targets**. Browser-evaluated test imports are resolved in their page,
  not relative to the test source file.
- Final extension build: **215 files**, checksum-verified allowlist and inventory;
  no checkpoint files/preload images. The audit now also rejects `.ort` weights.
- Two ASR cards among 13 total model cards; independent index links for both
  languages. All unrelated model families remain.

## Real inference observations

`npm run prepare:optional-asr-test-models` followed by
`npm run test:optional-asr-real -- --workers=1` exercises the actual packaged
MV3 graph, Nodes, Workers and native runtime. Every file is verified by
ModelAssetCache. HTTP is blocked before inference. Both languages passed two
sessions, Stop/tail drain, Cancel, cache reuse and Worker cleanup with **zero
inference requests or page errors**. Known speech text, file sizes, hashes and
provenance are in `tests/fixtures/moonshine-speech.json`; short committed WAVs
avoid a platform speech-synthesis dependency during tests.

The fixtures are natural-sounding **synthetic** Samantha/Kyoko speech, not human
recordings. They establish real decoding and lifecycle, not personal dictation
accuracy. [Machine-readable observations](asr-383-real.json) record the final run.
On this Chromium 153 host, with paced 100 ms blocks:

| Model | Provisional updates per run | First provisional from replay start | Stop drain |
| --- | --- | --- | --- |
| Japanese Small | 18 | 1.82–1.84 s | 0.36–0.38 s |
| English Medium | 11 | 1.81–1.86 s | 0.56–0.57 s |

First-provisional times include one second of leading silence and real-time
replay, not just model execution. Prepared-runtime Start is measured separately;
it is not cold-loading time. Native process peak memory was not measured;
transport/history bounds and backpressure are tested deterministically.

Japanese preserved all three sentences, including the meeting, speech-recognition
test and document request. It normalized 三時 to 3時 and appended **「はい。」**
which was absent from the fixture. This is a quality caveat; Japanese Small has
not been established as meeting the user's dictation quality bar. English
recognized all three sentences, normalizing “ten” to “10:00.” Both produced
real partials before finalization; the tests check all three expected clauses,
unique final IDs and exact downstream displayed text. Large downloads and manual
quality approval remain opt-in, outside default CI.
