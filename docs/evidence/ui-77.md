## Acceptance coverage

- Live navigation opens real separate Graph Editor/Models tabs while the same
  native Web Audio stream, workers, capture target and playback restoration stay
  active. Live-window navigation focuses the existing recorder without invoking
  the toolbar or requesting capture. Closing auxiliary pages leaves Live active.
- Start/Stop/finalize/Cancel, loading failures, tab closure/navigation, stale
  callbacks, provisional/final fallback, ordered source/translation pairing,
  clipboard copying and optional TTS playback/WAV use the production lifecycle.
- Editor tests exercise typed click and keyboard connections, actual port drag
  and drop, disconnect, node dragging at normal and 75% zoom, keyboard movement,
  settings inspector, palette, validation, save/load/reset, corrupt graph
  recovery, legacy preference migration and same-profile Chrome restart.
- Saving an edited graph during recording leaves the active Pipeline/Workers
  intact. A new session executes the saved transcription-only or TTS graph.
  Live reads the persisted graph on each start, avoiding a race with a delayed
  storage notification. Editor status shows draft, saved and active distinctions.
- Conflicting editor drafts are retained and rejected on Save until Load saved.
  Saves compare the current stored graph while holding an extension-origin Web
  Lock; Load saved reads the current stored graph rather than an older UI copy.
- Models inspects each real reviewed OPUS/TTS asset set independently; opening
  pages never downloads weights or creates inference/capture Workers. Both OPUS
  directions and TTS models have explicit preparation, progress, error/retry and
  cancellation. Complete fixture caches survive page recreation/profile restart;
  missing/evicted/corrupt assets stay missing and require deliberate recovery.
- Production model-card tests cover deletion, cross-page cache refresh, both TTS
  voice variants and shared-weight reuse/removal. Model controls do not modify
  the saved graph. The tiny #67 cache fixture can be Ready while all production
  models remain Not downloaded; it lives on a separate test page.
- Keyboard-reachable navigation, ports, node movement and settings have labels
  and visible focus. Status/alert regions and textual state labels convey meaning
  without color alone. Live, Models and Editor fit 440-pixel windows without
  document overflow; the graph itself scrolls. Reduced-motion media preserves
  usable controls. Wide editor canvas, contrast and inspector were visually
  inspected in the saved screenshots.

## Screenshots and fixture limits

[Live](ui-77-live.png), [Graph Editor](ui-77-graph.png) and
[Models](ui-77-models.png) are deterministic UI screenshots generated by
`tests/extension/graph.spec.js`. Live shows fixture source utterances with
translation off; the editor shows an unsaved translation branch while Live
continues running the saved transcription-only graph. Model cards use real
production manifest APIs with small deterministic TTS asset replacements, so
fixture byte counters are smaller than the production size estimates.
Screenshots contain no user speech or fabricated production inference claims.

Routine OPUS/TTS checks use small deterministic assets and simulated heavy
runtime inference behind the production Worker protocols. They establish UI,
cache integrity/lifecycle and executable graph routing, **not real OPUS/TTS
model inference or speech accuracy**. The default extension suite's real pinned
ReazonSpeech/Silero initialization and silence finalization under MV3 CSP passed;
native toolbar/capture tests use generated audio with deterministic recognition.

The four opt-in extension inference smokes were updated to operate the separate
pages but were **not run for #77**. Historical real-model results remain separately
recorded in [#71](translation-direction-71.md) and [#75](graph-75.md); they are not
claimed as a fresh check of this revision. Reproduction commands remain in
[the graph guide](../extension-graph.md) and
[the extension guide](../chrome-extension.md).
