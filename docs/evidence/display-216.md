# Display input tabs (#216)

Validated locally on 2026-11-05 with Playwright 1.63.0, Chromium 153.0.8010.12
and WebKit 26.6 on macOS. Nothing was pushed, published or commented on GitHub.

## Corrected contract

One Display is an independent view, and each `inputN` port is a switchable tab
inside it. Exactly one input panel is visible, at desktop and narrow widths.
Multiple Display nodes remain separate outputs. A single-input Display omits the
tab strip. The former node-tabs and input-columns contract from #212 is superseded.

Settings retains Add input / Remove last input. Optional `settings.inputLabels`
maps stable `inputN` identities to editable labels of at most 120 characters.
Blank/missing labels use `Input N`; duplicates never mix state. Removing the last
input removes only its label and wire. Existing numbered graphs need no rewiring
and legacy `Display.input` migration/recovery is unchanged. Settings persist
through Save/Load/Import/Export and take effect next session.

Switching changes presentation only. Every input keeps its complete latest
TEXT/pair/list snapshot while hidden. The pipeline and panel DOM remain in place;
scroll offsets, bottom-following intent and unchanged snapshot DOM are retained.
Copy belongs to the selected input. Hidden content and copy-status live regions
are quiet. Tabs have ARIA relationships, roving tabindex, wrapping arrows,
Home/End, pointer/touch activation and visible keyboard focus.

## Packaging and unverified scenarios

`npm run build:extension` was attempted and stopped with **Missing local models**.
The production model-complete bundle and real ASR/translation/summary inference
were not verified. No inference code or model preparation changed.

MV3 tests used source-only staging into ignored `dist/chrome-extension`, following
the procedure documented in [#212's packaging notes](display-212.md#packaging-and-limits):
the packager's `SHARED_FILES`, unchanged extension sources and manifest, followed
by existing test fixtures' controlled Workers/assets. This verifies the extension
boundary and production recorder/editor/session/renderer without claiming a full
model distribution. The screenshot example uses literal Text sources and requires
no inference replacement.

Physical touch hardware and screen-reader speech were not tested. Accessibility
coverage verifies DOM semantics, focus, keyboard operation, quiet inactive regions
and Chrome's trusted emulated touch events. No post-merge verification is claimed.
