Issue [#377](https://github.com/takahirox/my-audio-to-text/issues/377): safe multiline voice insertion

Implemented for the real Lexical 0.38.2 **plain-text plugin** and Draft.js 0.11.7 fixtures, using their DOM paste handlers. The strategy dispatches one untrusted `ClipboardEvent('paste')` with an in-memory `DataTransfer` containing only `text/plain`. This is a verified application event-handler path, not a trusted browser paste or a browser default action. No editor instance, private property, page-world injection, clipboard read/write, new permission, or site adapter is used. Single-line delivery retains the existing browser insertion path.

Investigation preceded the production change. The unchanged text-insertion suite passed 26 tests, including the old guard: select `world` in `hello world`, deliver `voice`, ` voice`, ` voice`, then `\nnext`; the last value was definitely uninserted and the model remained `hello voice voice voice`. The same sequence now commits `hello voice voice voice\nnext` in both real models.

Upstream source inspected

Lexical sources are pinned to commit `c75b8e105ff9612f0166af22a518be01045fa72b` (v0.38.2):

- [LexicalEvents.ts](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical/src/LexicalEvents.ts): `onBeforeInput`, `onInput`, `onKeyDown`, `onDocumentSelectionChange`, `addRootElementEvents`. Normal typing can use native text changes followed by reconciliation, or controlled insertion commands. Enter dispatches a line/paragraph command. A DOM paste dispatches `PASTE_COMMAND`; these listeners do not require `isTrusted`.
- [lexical-plain-text/index.ts](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical-plain-text/src/index.ts): `registerPlainText` installs text, line-break, paragraph and paste commands. `onPasteForPlainText` prevents the default, reads a genuine `ClipboardEvent` object's `clipboardData`, and runs an `editor.update` tagged `PASTE_TAG`.
- [clipboard.ts](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical-clipboard/src/clipboard.ts): `$insertDataTransferForPlainText` passes plain text to the selection's `insertRawText`. The rich-text handler is a different implementation; this fixture does not establish compatibility for every Lexical plugin/configuration.
- [LexicalSelection.ts](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical/src/LexicalSelection.ts): `RangeSelection.insertRawText` converts newline/tab parts into nodes and calls `insertNodes`. This differs from inserting literal text into one text leaf. Selection operations replace the selected range and position the resulting caret.
- [LexicalUpdates.ts](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical/src/LexicalUpdates.ts): `updateEditor`, `updateEditorSync`, `$commitPendingUpdates` commit pending editor state, reconcile nodes and call `updateDOMSelection`. [lexical-history/index.ts](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical-history/src/index.ts) registers an update listener and Undo/Redo commands; the multiline paste produces an undoable model change. The fixture's forced `setEditorState` render now uses `HISTORY_MERGE_TAG`, avoiding an artificial duplicate Undo entry.

Why the native command experiments fail in Lexical: recorded `execCommand` calls emit `input` events without the normal `beforeinput`/keyboard command sequence. The paragraph/BR changes never become model line-break nodes. `onInput` reconciles the selected text leaf through [$updateSelectedTextFromDOM](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical/src/LexicalUtils.ts); [LexicalMutations.ts](https://github.com/facebook/lexical/blob/c75b8e105ff9612f0166af22a518be01045fa72b/packages/lexical/src/LexicalMutations.ts) removes unrecognized child-list additions and restores managed DOM/selection. The recorded final model is `hello voicenext`, losing the break. Waiting between commands does not establish the missing model operation.

Draft.js sources are pinned to commit `f55fa0f8da080fea74ae3fa98860c41db85cbeea` (v0.11.7):

- [editOnBeforeInput.js](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/component/handlers/edit/editOnBeforeInput.js) uses `Modifier.replaceText` and `EditorState.push('insert-characters')`. Noncollapsed selections are handled in the model; safe native character insertion can defer the pending state to `editOnInput`. In React 18, this `onBeforeInput` is extracted from keyboard/composition/`textInput`/paste dependencies, not arbitrary DOM `beforeinput` dispatch: see [BeforeInputEventPlugin.js](https://github.com/facebook/react/blob/v18.3.1/packages/react-dom/src/events/plugins/BeforeInputEventPlugin.js).
- [editOnKeyDown.js](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/component/handlers/edit/editOnKeyDown.js) routes Return to [keyCommandInsertNewline.js](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/component/handlers/edit/commands/keyCommandInsertNewline.js), which uses `Modifier.splitBlock` and `EditorState.push('split-block')`.
- [editOnPaste.js](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/component/handlers/edit/editOnPaste.js) prevents default, reads `clipboardData`, splits text into lines, and calls [DraftPasteProcessor.processText](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/model/paste/DraftPasteProcessor.js). This creates `ContentBlock` records with text and character metadata; a block map becomes an inserted fragment. No trust check blocks this path in the pinned handler.
- [DraftModifier.replaceWithFragment](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/model/modifier/DraftModifier.js) removes the selected range then calls [insertFragmentIntoContentState](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/model/transaction/insertFragmentIntoContentState.js). The fragment preserves the original head/tail, inserts intermediate blocks, and sets `selectionAfter` at its end. [ContentState](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/model/immutable/ContentState.js) owns the immutable block map and before/after selections. [EditorState.push/undo/redo](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/model/immutable/EditorState.js) maintain history and restore those selections; paste uses `insert-fragment`, creating a history boundary.

Why the native command experiments fail in Draft: [editOnInput.js](https://github.com/facebookarchive/draft-js/blob/f55fa0f8da080fea74ae3fa98860c41db85cbeea/src/component/handlers/edit/editOnInput.js) reconciles unexpected native mutations as a spellcheck-style replacement of **one leaf**, using its offset key. Browser-created paragraphs are not a `ContentState` fragment. After multiline `insertText` or synchronous `insertParagraph`, the model becomes `next`, while rendered DOM contains `next\nnext`; `insertLineBreak` produces reordered text. With settling delays, paragraph insertion can invalidate the leaf/block mapping and cause an application error. The matrix captures the error and missing root rather than treating DOM appearance as success.

What an external content script can trigger

The app-owned APIs above explain the transformations; the extension cannot call `editor.update`, dispatch editor commands directly, or supply a new Draft `EditorState`. [Chrome isolated worlds](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts#isolated_world) separate page variables from content scripts while sharing DOM access. The implementation uses only DOM event constructors/dispatch on the already authorized original element.

Trusted ordinary typing and OS clipboard paste are positive controls driven by Playwright, not extension capabilities. `execCommand('paste')` has no effect without clipboard authorization; obtaining that authorization or replacing the user's clipboard is unnecessary here. Synthetic `beforeinput`/`input` have no trusted browser editing default. In this matrix `beforeinput` does nothing; `input` reaches Lexical's controlled text insertion branch and stores a literal newline in one text leaf, but does nothing in Draft. It is not a shared strategy. Synthetic paste works here only because the inspected framework handlers explicitly consume its supplied text and perform their own model updates. A site's custom handler can reject or ignore it; cancellation/`dispatchEvent` return values alone never confirm delivery.

Repeatable matrix and validation

[web-voice-377-matrix.json](web-voice-377-matrix.json) records the exact browser version, operations, event trust/input types, model document and model selection, raw DOM/HTML and DOM caret before insertion, after 120 ms reconciliation, after a forced application render, and after Undo/Redo. Draft `innerText` can include a layout BR in empty blocks; raw DOM and model state are kept separately. Random framework node keys are fixture state, not stable identifiers.

Run `EDITOR_MATRIX_WRITE=1 npx playwright test --config playwright.extension.config.js tests/extension/editor-multiline.spec.js --reporter=line` to regenerate it. Both frameworks start with `hello world`, select offsets 6–11, and insert `voice\nnext`.

Shared-strategy tests additionally cover insertion at a caret, replacement, newline-only text, empty editors, carets at both ends of existing lines, cross-line selection, CRLF/lone CR normalization, blank lines, literal HTML, repeated committed segments, manual typing at the resulting caret, subsequent render and Undo/Redo. Both authenticated output routes test the original repeated-segment sequence, duplicate suppression, manual edits, paste rejection, ordered recovery and explicit retry. Website microphone delivery rejection keeps capture and ASR workers healthy. General delivery regressions retain bounded queues, authorization, focus/target, IME, clipboard and ambiguous-edit protections.

The multiline path keeps the existing asynchronous policy/focus/selection/composition checks. Its `beforeinput` preflight is text-free: literal newline data makes Lexical perform an edit during preflight. Only the later paste carries the segment. Successful delivery also requires a collapsed DOM caret at the end of that insertion; a mismatched caret is ambiguous. Newlines are normalized to LF before dispatch. Unavailable constructors or an ignored/cancelled paste with no observable effect return `not-inserted`; a caret-only effect or changed/reconciled content that fails verification returns `ambiguous` and cannot be replayed. There is no native-command or DOM-mutation fallback after paste. Custom configurations and future versions remain subject to observable reconciliation checks; a delayed private-state rewrite beyond that window cannot be proved absent by any generic DOM strategy. No logged-in production-site compatibility is claimed.
